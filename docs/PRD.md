# Agent 驱动的知识库问答 Demo｜PRD

## 文档目的

请依据本文构造一个最小但完整的知识库问答 Demo。目标不是复刻某个现有项目的界面、目录或技术栈，而是复用这一思路：把用户问题连同检索规则交给一个已经具备工具能力的外部 Agent，观察它检索知识源的过程，最后展示回答及依据。实现者可以在此基础上加入自己的产品念头，样式、品牌、交互细节和工程选型均可自行定义。

默认成品是本机单用户工具，不是多人知识库平台。优先完成一条真正可运行的问答链路，不要先建设向量库、Agent 框架、账号系统或复杂管理后台；除非用户明确要求，否则不自建 RAG，也不重新实现 Agent 已有的文件读取、搜索和推理能力。

## 开始前的确认

Agent 应先自动探测可用的 Agent CLI 或 API、版本、可读取的运行事件、已安装的 Skill/规则文件和端口占用，能确认的不要询问用户。知识源的绝对路径或连接方式必须向用户确认，因为它没有可靠默认值；若知识源不是本地 Markdown 目录，还应确认其格式和只读访问方法。

其余信息尽量采用默认值：运行范围默认为本机单用户，监听 `127.0.0.1`；交互默认为一次提问对应一次独立任务；超时默认 300 秒；界面默认为一个输入框、过程区域和答案区域；回答语言跟随用户；无明确需求时不保存历史、不提供原文查看器、不做登录。若用户主动表达了视觉风格、用途或附加功能，将其视为产品方向而非本 PRD 的硬性要求。

只有在自动探测失败或选择会明显改变产品时才集中澄清：使用哪个 Agent 运行时及 Skill、是个人使用还是团队使用、是否必须展示工具过程和引用、是否需要历史记录或原文查看。端口仅在默认端口被占用时询问。涉及安装软件、真实模型费用、启动长期服务或开放网络访问时，应先取得用户同意。

## 最小产品闭环

用户进入页面后输入一个自然语言问题并提交。后端为本次请求生成唯一任务标识，把问题拼接到可配置的提示词模板中；模板可以指定要使用的 Skill、知识源和回答边界，但不得把路径、密钥或个人文案硬编码进公共源码。随后通过 CLI 子进程或 Agent API 创建一次独立运行，并把任务与其真实会话关联起来。

页面应在等待期间持续给出可理解的进度，而不是长时间停在无反馈状态。最低要求是展示启动、检索中、完成或失败；如果运行时能够提供工具调用、工具结果或公开的推理摘要，可以增量展示，但原始隐藏思维链不是产品依赖，也不应为了界面效果而要求模型输出。SSE、WebSocket、长轮询或官方事件 API 都可以使用，只要断线、心跳和任务结束行为明确。

Agent 完成后，页面展示最终回答。回答应尽量包含可核验的依据，例如文档标题、文件相对路径、URL 或数据记录标识；引用能否点击、是否渲染原文、是否展示元数据均为可选增强。知识源没有答案时应明确说明，而不是用通用知识补齐。进程异常、会话无法关联、读取失败和超时必须转换成用户可见的错误，诊断信息可以保留，但不应无上限地暴露日志或敏感数据。

同一时间的多个任务不得读取到彼此的事件或回答。会话关联不能只依靠“最近创建”这类模糊条件；应优先使用运行时直接返回的 session/run ID。若运行时不返回 ID，可以在提示词或请求元数据中加入每次运行唯一的关联标识，再以时间和首条消息作为辅助校验。最小 Demo 可以限制并发数，但必须明确行为，不能悄悄串线。

## Skill 与回答契约

Skill 或等价规则文件负责告诉 Agent 去哪里查、允许使用哪些工具、如何判断证据充分，以及按什么结构回答。默认规则应要求先定位索引或目录，再搜索关键词并阅读少量最相关材料；仅基于知识源作答，内容冲突时并列说明，没有依据时直接承认；引用使用真实存在、相对知识源稳定的标识。具体检索步骤、语言、篇幅和回答格式由用户自行调整。

“只读”默认只是对 Agent 的行为要求，并不等于操作系统权限隔离。若 Agent 拥有终端或通用文件工具，提示词可能被绕过，知识库内容本身也可能包含提示词注入。个人本机 Demo 只需清楚披露这一边界；若用户要求团队或生产使用，则必须进一步设计只读文件权限、工具白名单、身份认证、访问控制、限流、审计和数据隔离，不能仅靠 Skill 宣称安全。

## 实现选择与可选能力

外部 Agent 默认优先复用用户已经安装并配置好的运行时；若检测到 Hermes，可参考一次性 `hermes chat` 调用并预加载指定 Skill，但实现不得假设 Hermes 是唯一选择。过程事件优先使用运行时的公开 API；读取 CLI stdout、日志或会话数据库属于兼容性适配方案，应隔离在适配层，并记录已验证版本，因为内部格式随升级变化时可能失效。

后端可以使用任意轻量 Web 框架，前端可以是纯静态页面或任意框架。建议内部统一成少量事件类型：`status` 表示阶段变化，`tool_call` 和 `tool_result` 表示可选的工具过程，`answer` 表示最终回答，`error` 表示不可恢复错误，`done` 表示任务结束；事件至少包含任务标识和相对时间。具体字段、动画、卡片和配色不属于验收条件。

历史记录、答案缓存、重新生成、导出、预设问题、主题切换、知识源索引、Markdown 原文查看器和多版本答案全部是可选功能。用户没有提出相关念头时不要为了“完整”而加入；若加入本地存储，应说明容量、清除方式和隐私影响。若允许通过引用读取本地文件，必须只允许访问配置的知识源范围，并防止 `..`、符号链接或编码变体造成路径穿越。

配置应与源码分离，至少容纳 Agent 可执行文件或服务地址、知识源、Skill/规则名称、提示词模板、超时和监听地址。提供不含真实个人路径与凭据的示例配置，真实配置默认不进入版本控制。启动时应尽早检查关键路径、运行时和 Skill 是否可用，并给出能指导修复的错误。

## 当前 Demo 的参考实现（非强制）

当前 Demo 在 Windows 10 上验证，使用 Hermes Agent v0.19.0（git 安装）、Python 3.12.9 和 Flask 3.1.3；Node.js 仅用于运行前端离线测试，页面本身没有构建步骤。这组版本只是已经跑通的环境快照，不是本 PRD 的依赖约束。Hermes CLI、Skill 和会话数据库的接口都可能随上游变化，采用此方案时应记录自己的验证版本。

运行前从独立配置文件读取 Hermes 可执行文件、`state.db`、知识库根目录、Skill 名称、工作目录、超时、监听地址和站点文案。当前实现把用户问题包装成下面的完整提示词，并以参数数组而非 shell 字符串启动子进程：

```text
提示词：使用 {skill} skill，回答用户的问题：{question}

命令：<hermes_exe> chat
      -q "<完整提示词>"
      -s <skill>
      --source <source_tag>
      -Q
```

这里的 `-s` 负责在新会话中预加载指定 Skill，提示词中的“使用该 skill”则再次明确本轮任务意图；两者共同把用户问题与检索规则关联起来。`-Q` 使用适合程序调用的安静模式，`--source` 只给会话写入来源标签，便于辨认和排查，不承担可靠的任务匹配。Skill 需要事先安装到 Hermes 能发现的位置，其中写明知识库路径、允许使用的检索工具、只读行为要求、无依据时的处理方式和引用格式；更换 Skill 即可改变检索策略和回答风格，而不必修改 Web 应用。

当前数据链路如下，其他实现可以替换其中任意一段，只要保持任务隔离、过程反馈和最终结果这三个产品能力：

```text
浏览器提交问题
  → POST /api/ask 创建内存任务并返回 task_id
  → 后台线程 spawn 一次 hermes chat 子进程
  → Hermes 创建 session，并持续向 state.db 写入 messages
  → 后端以只读 SQLite 连接轮询新消息
  → 按启动时间 + 首条 user 消息等于完整提示词寻找候选 session
  → 在进程内原子认领 session，避免相同问题并发重复认领
  → reasoning_content / tool_calls / tool message / assistant content
     被转换成 reasoning / tool_call / tool_result / answer 等内部事件
  → GET /api/stream/<task_id> 通过 SSE 增量推给浏览器
  → 子进程退出后补读最后一条非空 assistant content
  → 发送 answer、done 或 error，页面完成展示
```

`state.db` 使用 SQLite WAL，当前后端通过只读 URI 打开，并约每 1.2 秒按消息自增 ID 增量查询。涉及的核心数据是：`sessions.id` 与 `sessions.started_at` 用于定位会话；`messages.session_id` 和 `messages.id` 用于增量读取；`role`、`content`、`reasoning_content`、`tool_calls`、`tool_name` 用于还原过程。工具参数和结果尽量原样进入内部事件，展示层再提取文件名、关键词和成功状态；同时设置长度上限，避免日志无限增长。

浏览器先用 `POST /api/ask` 取得任务标识，再用 `EventSource` 连接对应 SSE 地址。后端为任务保留事件列表和条件变量，因此连接稍晚时仍能重放此前事件；当前参考实现没有持久化的恢复游标，断线重连可能重放已有事件，更严格的实现应增加 event ID 和前端去重。当前 Demo 还会扫描知识库中的 Markdown 文件生成文件名到相对路径的索引，把回答里的引用链接到一个受目录边界保护的原文接口；这一段以及浏览器 localStorage 历史均属于可选体验层，不影响核心问答链路。

## 安全与隐私边界

默认服务仅绑定本机回环地址。知识源内容可能被 Agent 发送给模型服务商，过程事件可能包含文件内容、命令、路径或推理摘要；这些事实必须在使用说明中写清楚。密钥不得进入前端、日志、示例配置或代码仓库，错误信息在展示前应限制长度并考虑脱敏。

如果用户选择团队模式，Agent 必须暂停默认实现并补充澄清：谁可以访问、不同用户是否共享知识源、模型费用由谁承担、日志保存多久、是否允许查看原文，以及部署网络边界。未回答这些问题前，只能交付本机 Demo，不能把监听地址改为公网可达后声称已经支持团队使用。

## 验收标准

在一台满足已声明前置条件的机器上，用户只需填写一份配置并准备一个最小知识源，即可启动应用、提交一个知识源中确有答案的问题，并在超时范围内看到明确进度和最终回答。回答至少给出一个可核验来源；对知识源中不存在的问题应明确缺少依据；Agent 不可用、Skill 缺失、会话关联失败和运行超时均有清晰错误。

至少提供零模型费用的离线检查，覆盖配置加载、页面或接口可访问、任务隔离逻辑和引用路径边界；真实端到端测试必须标注会调用模型并可能产生费用，执行前取得用户同意。最终交付至少包含源码、示例配置、启动说明、安全边界和最小测试。只要上述闭环成立，具体 UI、框架、存储方式和附加功能不同，仍视为符合本 PRD。
